## Evidence and provisional cause

The [continuation audit](V4_CONTINUATION_GUARD_AUDIT.md) reports 99 VERIFIED_PARTIAL groups, 8,764 distinct remote pixels and 4,263 original gray-254 pixels. All 105 handoff groups instead contain 8,785 remote pixels and 4,282 gray-254 pixels. These populations must remain separate. The audit's 5,207 low-contrast background **candidates** are not proven background. Its nearest geometry-matched controls contain unrepresented BINARY content; 124 triggered placements out of 297 are not a false-positive rate. Graph-empty means absent from that representation, not physically blank.

The provisional root cause is an evidence-type mismatch: the predicate detects source contrast and adjacency, which do not identify physical musical ink. BINARY and glyph support corroborate processed support, not original-pixel identity. Connectivity through staff can join unrelated physical structures. Exact contribution and ownership at staff/notation/watermark crossings remain unresolved. The prior audit's synthetic gray-254 tail demonstrates predicate behavior, not the prevalence of real antialias or watermark errors. No prior audit is rerun or modified here.

## Freeze, sampling, and denominators

A study custodian freezes protocol version, source/manifest hashes, roster/roles, and a timestamp before constructing a sample. A later change requires a new version and new untouched sample. The fixed seed is `capomatic-independent-ink-v1-2026-10-18`. Sampling reads dimensions and source identity only, never intensities, BINARY, graph emptiness, remote sets, guard triggers, candidate classifications, gray thresholds, or desired outcomes.

**Prevalence arm:** partition the entire original page into a 4 × 4 grid. Cell `(c,r)` contains integer pixels with `floor(cW/4) <= x < floor((c+1)W/4)` and the analogous y bounds. Rank every eligible pixel within its cell by the unsigned lexicographic bytes of SHA-256 of the UTF-8 string `seed|source_sha256|prevalence|c|r|x|y`, using decimal integers without padding. Break a hash tie by `(y,x)`. Select the first six distinct pixels per cell: 96 anchors, no replacement. Retain page edges and white-appearing areas. The denominator is all `W*H = 8,703,348` source pixels; publish each of the 16 cell populations and six selected coordinates. Never replace a selected anchor because it is uninteresting or unlabelable. On a future small page select `min(6, cell_population)` and report the shortfall.

Each anchor gets an unmodified 65 × 65 source crop, a 513 × 513 context crop and access to the original full page. For odd crop width `s`, use half-open bounds `[x-floor(s/2), x+floor(s/2)+1)` and analogous y, clipped to page bounds. Do not pad, rescale, enhance contrast, interpolate or highlight within source pixels; specify the anchor's local integer coordinate separately. Integer nearest-neighbor zoom is permitted in the viewer. For each selected anchor, compute SHA-256 of UTF-8 `seed|source_sha256|presentation|x|y` using the same integer encoding as sampling. Its public ID is `p` followed by the full lowercase hexadecimal digest. Present all arms together in ascending digest-byte order, breaking ties by `(y,x)`; both annotators receive the same order and identical packets. A digest collision between distinct coordinates invalidates packet creation rather than exposing coordinates in the ID. Annotation packets contain no stratum, global coordinate, file naming clue to an outcome, BINARY, semantic label, guard result or contrast value. Full-page source context naturally reveals page appearance; blinding cannot hide that.

**Diagnostic arm:** nominate up to one anchor per completed 64 × 64 source tile per each of four source-only visual motifs: apparent notation/staff crossing; apparent pale overlay/text crossing; apparent fine notation edge; low-structure appearance. An independent source-only screener, who cannot access guard/BINARY/semantic evidence, examines every tile in a fixed row-major full-page tessellation, clipped at edges. Record examined tiles, all motif nominations and coordinates, unavailable/unclassifiable tiles and absence of nominations. A tile may nominate several motifs; each motif gets at most one anchor per tile. The motifs are screening hypotheses, never final physical labels or certified blanks. Finish and freeze the entire nomination list before ranking. Do not show screener tags to primary annotators.

Rank nominations within each motif with `seed|source_sha256|diagnostic|motif|x|y`, then `(y,x)`. Process motifs in the JSON order, taking eight unique anchors per motif; exclude prevalence anchors and previously selected diagnostic anchors, walking down the ranked list to fill the quota. If exhausted, retain the shortfall without substitutions or expanded screening. Thus there are at most 32 diagnostic anchors. Publish per-motif nominations, duplicate exclusions, eligible-after-exclusion denominators and selected counts. This arm characterizes nominated difficult appearances; it estimates neither page prevalence nor guard accuracy. The diagnostic screener's choices can bias the motif population and must be disclosed.

Selected target pixels are unique, but their viewing windows can overlap. Publish selected-anchor counts, unique coordinates, unique crop rectangles, pair counts whose 65 × 65 or 513 × 513 crops overlap, and the pixel union area of each crop size. Report same-label agreement for repeated coordinates if duplicates enter through an error; invalidate the sample and regenerate from the unchanged protocol rather than treating repeats as independent observations. Overlap is context dependence, not extra sample size. No confidence interval or power claim is made for this small deterministic sample.

## Blinded annotation and independent evidence

Recruit two independent human annotators with music-reading and raster-inspection experience, plus a third adjudicator. None may be the guard designer, diagnostic screener, packet maker or this assistant. Record expertise, conflicts, prior exposure and role separation. The custodian can handle hashes and mapping but cannot supply primary labels. Two model-generated answers or one person's duplicate pass are not independent labels. If the roster cannot meet these conditions, mark independence pending; do not silently relax it.

Train on separate, consented source examples outside this page and all future evaluation pages. Include ordinary notation, watermark, text, staff crossings, mixed/ambiguous gray boundaries and abstentions. Synthetic examples may explain interface mechanics but cannot establish real-image accuracy. Exclude all training/calibration coordinates and pages from evaluation. Freeze instructions before evaluation; no feedback, discussions or per-case corrections between the two annotators.

Primary labels describe the **anchor pixel**, using source-only context. They record a nonempty set of physical-content possibilities from `MUSICAL_NOTATION`, `STAFF`, `TEXT`, `WATERMARK_OR_GRAPHIC`, `PAPER_OR_BACKGROUND`, `UNKNOWN`; boundary/contribution possibilities from `INTERIOR`, `ANTIALIAS_OR_PARTIAL_COVERAGE`, `OVERLAP_OR_CROSSING`, `UNKNOWN`; certainty `RESOLVED`, `UNCERTAIN` or `ABSTAIN`; and a short rationale. Labels are multi-label possibilities, not an exclusive segmentation. A pale pixel may receive notation + watermark + antialias + crossing + UNKNOWN. `RESOLVED` means the annotator judges the stated contributions visible; it does not prove an acquisition history. Lack of visible evidence may justify UNKNOWN, never a forced foreground/background choice. Abstention retains the row and reason.

Freeze and hash both independent primary label files before any adjudication. The third reviewer receives source-only packets and both frozen rationales, documents agreements/disagreements and preserves alternatives or UNKNOWN when source evidence cannot resolve them. Freeze and hash adjudicated physical labels **before** unblinding. Retain original disagreements; never replace primary files with consensus. Annotation collection is not complete until identity/role records, all rows including abstentions, signed or timestamped freezes, packet provenance and independent adjudication are available.

After the physical-label freeze, the custodian may join separate tables for original source bytes/intensity, saved BINARY support, guard membership/outcomes and persisted semantic support. None becomes a revision to source labels. Late corrections are versioned corrections with reasons, preserving the first frozen analysis. Study designers cannot fill missing labels themselves. Sharing a source raster between arms is necessary, but shared model representations are not an independent truth source.

**Ownership is a separate uncertainty lattice**, not inferred from physical identity: retain a set of possible contributors/owners plus an `unresolved` flag. Empty + unresolved means UNKNOWN, a singleton + resolved means supported UNIQUE, multiple + resolved means supported SHARED, multiple + unresolved means possible alternatives or mixed contributions. Source-only primary labels start with unresolved ownership and no implementation group IDs. Any later ownership claim needs separately recorded human musical attachment reasoning and direct source evidence, with contributor IDs, ambiguous alternatives and adjudication; graph relations may be compared after freeze but cannot certify that claim. Even resolved musical identity does not authorize moving or deleting the pixel. At crossings retain mixed/unknown contribution unless independently separable.

## Frozen analysis and stopping rules

Report physical-label sets, uncertainty and abstentions for each arm separately. For prevalence, publish per-cell label/UNKNOWN counts over all selected rows and the page-area-weighted descriptive label fraction `sum(N_h * count_h(label)/n_h) / sum(N_h)`; labels can overlap, so these fractions need not sum to one. Publish actual populations, `n_h`, missing/abstain denominators and worst-case bounds assigning every unresolved/missing case to either side. Resolved-only fractions are supplemental and must state their smaller denominator. The study describes one known development page and has no generalization or accuracy guarantee.

Before adjudication, publish exact-set agreement for physical and boundary axes, per-label 2 × 2 tables over paired rows, disagreement count, each annotator's UNKNOWN/ABSTAIN rate, and overlap-window statistics. State paired, unpaired and total denominators. Do not pool diagnostic and prevalence rows. After freeze, compare BINARY/guard/semantic observations against resolved labels, keeping musical-only, non-musical-only, mixed and unknown/abstain rows separate. Report cell counts and unique-anchor denominators, including unresolved rows. A mixed pixel is never counted as a clean non-musical suppression success. Small or empty cells stay small or empty; do not tune sampling to fill desired outcome cells.

Stop collection at the fixed quotas or declared shortfalls, not at a desired agreement, false-positive count or rule outcome. Halt interpretation on source/hash mismatch, blinding breach, ineligible annotator, missing provenance or altered protocol; record the failure and create a new version/sample if needed. No dropping disagreements, iterative resampling, relabeling after guard reveal, threshold search or tuning on jayu. Any musical, mixed or unknown case in a proposed suppression population remains a blocker. Even an entirely resolved non-musical sample does not authorize implementation or prove all unsampled pixels safe.

Before evaluating a future candidate rule, preregister that rule, its failure criteria and a separately acquired multi-page holdout roster whose source hashes were locked before label/outcome access. Use the same source-first process, exclude calibration and development pages, and keep holdout labels sealed from rule authors until the candidate is fixed. After holdout failure, report it; any revised rule requires a new untouched holdout. This design does not claim those pages, labels, candidate rule or performance requirements already exist. No threshold is learned from this study.

## Recommendation and present limits

The next implementation recommendation is an offline, source-only packet builder and separated, immutable label/audit tables implementing this contract. First obtain the independent roster and labels. Keep the current blocking guard until independent evidence and a separate ownership-safe design justify a proposed change. An eventual analysis-only witness can record source contrast, processed support, physical labels and ownership uncertainty as separate fields; it must not collapse them into an automatic ownership decision. This is a recommendation, not authorization to run a next phase.

No packet, annotation collection, adjudication, diagnostic nomination, holdout selection, guard tuning, runtime change, renderer, API, Audiveris, Docker or FullAcceptance run is included here. The protocol is frozen as a design artifact; sampling and human-label collection remain pending. Targeted validation checks protocol structure and input integrity, and the existing V4/V3 music/gate tests protect the untouched implementation. It cannot verify human annotator independence or physical truth before those external observations exist.
